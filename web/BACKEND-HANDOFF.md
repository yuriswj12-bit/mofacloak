# 后端接入交接

当前是可交互 UI 原型，不是运营面板的生产部署。后端可使用已有面板接口适配，避免重复开发账务和节点计量。以下是建议接口边界，不代表已有接口。

| 模块 | 需要的数据 / 操作 |
| --- | --- |
| 账户与邀请制登录 | 服务端会话、邀请校验、用户资料、退出、注册权限 |
| 套餐目录 | ID、价格、周期、流量、设备限制、地区、真实共享等级、上下架 |
| 我的套餐 | 生效套餐、到期时间、月度用量、重置时间、状态 |
| 订阅 | 带访问控制的订阅 URL、客户端格式适配、令牌重置、二维码 |
| 订单与支付 | 服务端计算价格、积分预占、创建订单、取消、支付状态、幂等支付回调、权益开通 |
| 积分 | 统一时区、每日签到唯一约束、积分流水、奖励/抵扣/取消返还，全部服务端核算 |
| 礼品卡 | 服务端生成不可猜兑换码、绑定订单、过期时间、原子单次兑换、权限 |
| 邀请 | 名额、邀请码、受邀记录、奖励规则、防重复归因 |
| 工单 | 创建/回复/关闭、用户归属、客服后台、通知、脱敏、附件限制 |
| 知识库 | 已发布文章、分类、版本、搜索、客户端实际截图 |
| 设置 | 资料、通知偏好、邮箱验证，安全设置需独立认证流程 |

## 必须替换的原型逻辑

1. 用服务端数据源替换 `useSaved` 和 PLANS 常量；不得把 localStorage 当作授权与账务依据。
2. 删除「模拟支付完成」按钮。订单由支付服务回调驱动；重复回调不重复发权益或积分。
3. 套餐变更需定义升级/降级/续费、生效时间与已有用量处理；原型仅展示流程。
4. 礼品卡兑换与积分签到要有数据库唯一约束和事务，防止跨设备、跨标签页重复处理。
5. 从节点后端读取真实使用量；展示双向/单向计量说明与重置周期。
6. 订阅凭证不可进入日志、分析埋点或第三方二维码接口；二维码在客户端本地生成。订阅格式需要与实际客户端验证。
7. 无钱包、不预存余额；订单和账单保留在同一个「我的订单」模块。
8. 正式价格、退款/服务条款、积分过期与兑换规则、设备限制需产品确认后上线；当前都是演示值。

## 验收原则

出口住宅属性、共享承诺和支持网站，以供应商及实际交付测试为准；UI 不承诺永久零风险或所有检测满分。上线前完成邀请制账户隔离、订单越权、令牌泄漏、支付幂等和计量一致性检查。
